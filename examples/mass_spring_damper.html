Mass–spring–damper

A two-state finite-dimensional port-Hamiltonian model

Let \(q\) be the displacement of a point mass, \(p=m\dot q\) its momentum, \(m>0\) the mass, \(k>0\) the stiffness and \(c\geq0\) the viscous damping coefficient. The applied force is \(f(t)\). Then

\[\dot q = \frac{p}{m},\qquad \dot p = -kq-\frac{c}{m}p+f(t).\]

Use the energy variables \(z=(q,p)^\top\) and Hamiltonian

\[H(z)=\frac12 kq^2+\frac{p^2}{2m}.\]

The co-energy variables are

\[e_q=\frac{\partial H}{\partial q}=kq,\qquad e_p=\frac{\partial H}{\partial p}=\frac{p}{m}.\]

The port-Hamiltonian representation is

\[\begin{split}\dot z = \underbrace{\begin{bmatrix}0&1\\-1&0\end{bmatrix}}_{J} \begin{bmatrix}e_q\\e_p\end{bmatrix} -\underbrace{\begin{bmatrix}0&0\\0&c\end{bmatrix}}_{R} \begin{bmatrix}e_q\\e_p\end{bmatrix} +\begin{bmatrix}0\\1\end{bmatrix}f(t),\qquad y=e_p.\end{split}\]

Since \(J=-J^\top\) and \(R\succeq0\), the continuous power balance is

\[\dot H=-c\,e_p^2+f(t)e_p.\]

Discretization and code

This is an ODE, not a spatial PDE. The new lumped port kind assigns one GetFEM DOF to each state and its co-state. The reference interval \((0,1)\) in the script is only used to assemble scalar GetFEM weak forms; it is not a physical spring mesh.

The implementation follows the standard SCRIMP workflow:

  1. Create a DPHS and its reference Domain.

  2. Add two State objects with kind=”lumped”, and their CoState objects.

  3. Call add_lumped_port for q and p (not add_FEM).

  4. Add mass, interconnection, damping, forcing and constitutive Brick objects.

  5. Initialize the two states and their constitutive co-energies, integrate with implicit PETSc BDF2, then plot.

The factor /ell in each brick compensates for the integration over the reference interval length ell, so that the resulting scalar equations are exactly those above. The time-dependent forcing is assembled as a nonlinear/residual brick rather than as a fixed matrix term; this is needed in SCRIMP’s current GetFEM assembly path.

Initial consistency is not a time-integration step. The dynamical initial values are prescribed as q0=0.4, p0=0. Since this finite-dimensional model has explicit constitutive laws, the exact algebraic initialization is simply

\[e_q(0)=kq_0=2,\qquad e_p(0)=p_0/m=0.\]

The example now assigns these two genuine scalar GetFEM co-energy variables directly and disables pseudo-time relaxation. This preserves all physical initial data instead of moving the momentum to satisfy the constraints. It does not change the mass, interconnection, damping, forcing or the subsequent BDF2 integrator. The generic SCRIMP DAE initializers are unchanged.

The complete runnable source is:

examples/mass_spring_damper.py
# SCRIMP - Simulation and ContRol of Interactions in Multi-Physics

# github: https://github.com/g-haine/scrimp

"""Mass--spring--damper: a finite-dimensional port-Hamiltonian example.

State x=(q,p), with displacement q and momentum p=m*q_dot.
    H(q,p) = k*q**2/2 + p**2/(2*m)
    e_q = dH/dq = k*q,  e_p = dH/dp = p/m
    q_dot = e_p
    p_dot = -e_q - c*e_p + f(t)

Power balance: H_dot = -c*e_p**2 + f*e_p.

Each lumped port has a **single** DOF. The interval used here is only
a normalization domain for GetFEM's weak-form assembly; it is NOT a
spatial discretization of the oscillator.
"""

import numpy as np
from pathlib import Path
import scrimp as S


def mass_spring_damper(
    final_time=8.0, time_step=0.01, plot=False, *,
    factor_solver=None, output_dir=None,
):
    """Simulate the forced, damped oscillator using lumped dynamic ports.

    Returns
    -------
    scrimp.DPHS
        Solved system with Hamiltonian terms and time histories.

    Prescribe exact constitutive co-energies at t=0 to preserve
    the physical initial states (q0,p0), without pseudo-time evolution.
    """
    mass = 1.5
    stiffness = 5.0
    damping = 0.25
    interval_length = 1.0

    sys = S.DPHS("real")
    sys.set_output_name("mass_spring_damper")
    sys.set_domain(S.Domain(
        "Interval", {"L": interval_length, "h": 1.0},
        mesh_output_dir=sys.get_output_path("mesh",create=False),
    ))

    q = S.State("q", "Displacement", "lumped")
    p = S.State("p", "Linear momentum", "lumped")
    for state in (q, p):
        sys.add_state(state)
    sys.add_costate(S.CoState("e_q", "Spring force", q))
    sys.add_costate(S.CoState("e_p", "Velocity", p))

    # Unlike FEM("q", ...), this registers a single scalar DOF.
    sys.add_lumped_port("q")
    sys.add_lumped_port("p")

    for key, val in {
        "ell": interval_length,
        "osc_mass": mass,
        "spring_k": stiffness,
        "damp_c": damping,
    }.items():
        sys.gf_model.add_macro(key, str(float(val)))
    sys.gf_model.add_macro("force", "0.2*sin(2*pi*t)")

    bricks = [
        S.Brick("M_q", "q*Test_q/ell", [1], dt=True, position="flow"),
        S.Brick("M_p", "p*Test_p/ell", [1], dt=True, position="flow"),
        # Canonical Dirac interconnection J = [[0,1],[-1,0]]
        S.Brick("J_qp", "e_p*Test_q/ell", [1], position="effort"),
        S.Brick("J_pq", "-e_q*Test_p/ell", [1], position="effort"),
        S.Brick("Damping", "-damp_c*e_p*Test_p/ell",
                [1], position="effort"),
        # A time-only source is classified non-linear so that it is
        # assembled on every residual evaluation.
        S.Brick("External_force", "force*Test_p/ell", [1],
                linear=False, position="effort"),
        S.Brick("Spring_law", "(spring_k*q-e_q)*Test_e_q/ell", [1]),
        S.Brick("Momentum_law", "(p/osc_mass-e_p)*Test_e_p/ell", [1]),
    ]
    for brick in bricks:
        sys.add_brick(brick)

    q0, p0 = 0.4, 0.0
    sys.set_initial_value("q", q0)
    sys.set_initial_value("p", p0)
    # True zero-dimensional variables, one GetFEM DOF each.
    # Both algebraic laws hold at t=0 without changing q0 or p0.
    sys.gf_model.set_variable("e_q", np.array([stiffness*q0]))
    sys.gf_model.set_variable("e_p", np.array([p0/mass]))
    # An omitted factor_solver leaves the current SCRIMP/PETSc default
    # (MUMPS) untouched. Users can explicitly select superlu (serial),
    # superlu_dist (MPI), or another PETSc-supported LU backend.
    scheme = {}
    if factor_solver is not None:
        scheme["pc_factor_mat_solver_type"] = factor_solver
    # Already-consistent lumped data need no artificial initialization TS.
    sys.set_time_scheme(
        ts_type="bdf", ts_bdf_order=2,
        ts_exact_final_time="matchstep",
        ts_adapt_type="none",
        ksp_type="gmres", pc_type="lu",
        t_0=0.0, t_f=float(final_time),
        dt=float(time_step), dt_save=float(time_step),
        init_step=False,
        **scheme,
    )
    sys.solve()

    sys.hamiltonian.set_name("Mass--spring--damper energy")
    sys.hamiltonian.add_term(
        S.Term("Spring potential", "spring_k*q*q/(2*ell)", [1])
    )
    sys.hamiltonian.add_term(
        S.Term("Kinetic", "p*p/(2*osc_mass*ell)", [1])
    )

    if plot:
        destination=(
            Path(output_dir) if output_dir is not None
            else sys._output_root
        )
        sys.plot_Hamiltonian(
            save_figure=True,filename="mass_spring_Hamiltonian.png",show=False
        )
        # Original GetFEM/PETSc accepted states, not probe-generated art.
        sys.mass_spring_visuals = render_mass_spring_visuals(
            sys,destination,mass=mass,stiffness=stiffness,damping=damping
        )
    return sys


def render_mass_spring_visuals(system, folder, *, mass, stiffness, damping):
    """Original lumped-DOF time series, physical power and GIF.

    Only the saved PETSc/GetFEM solution drives every figure and the
    mechanical schematic. This rendering is part of the canonical
    user example, not a research or acceptance helper. It never
    invents an FEM space for a zero-dimensional oscillator.

    BDF2 energy-power identity is evaluated at k>=2 only; the PETSc
    internal startup half-step is not an ordinary BDF1 interval.
    """
    import io
    import json
    from petsc4py import PETSc
    import matplotlib.pyplot as plt
    from PIL import Image

    times=np.asarray(system.solution["t"],dtype=float)
    q=np.asarray(system.get_solution("q"),dtype=float).ravel()
    p=np.asarray(system.get_solution("p"),dtype=float).ravel()
    eq=np.asarray(system.get_solution("e_q"),dtype=float).ravel()
    ep=np.asarray(system.get_solution("e_p"),dtype=float).ravel()
    H=np.asarray(system.get_Hamiltonian(),dtype=float).ravel()
    n=len(times)
    if (n<3 or any(x.shape!=(n,) for x in (q,p,eq,ep,H))
            or not all(np.all(np.isfinite(x))
                       for x in (times,q,p,eq,ep,H))
            or not np.all(np.diff(times)>0.)):
        raise RuntimeError("Missing authentic finite-dimensional GetFEM history")
    if not np.allclose(np.diff(times),np.diff(times)[0],rtol=0.,atol=1e-10):
        raise RuntimeError("Canonical mass-spring BDF2 visualization requires fixed dt")
    dt=float(times[1]-times[0])
    if system.last_ts_converged_reason<=0 or system.last_ts_steps!=n-1:
        raise RuntimeError("Cannot visualize an unconverged lumped simulation")

    force=0.2*np.sin(2.*np.pi*times)
    velocity=p/mass
    dissipation=damping*ep*ep
    input_power=force*ep
    analytic_H=0.5*stiffness*q*q+0.5*p*p/mass

    # Canonical lumped co-energy consistency; check each true saved
    # GetFEM variable before drawing potentially misleading plots.
    coenergy_error=max(float(np.max(np.abs(eq-stiffness*q))),
                       float(np.max(np.abs(ep-velocity))))
    Hamiltonian_error=float(np.max(np.abs(H-analytic_H)))
    if coenergy_error>1e-8 or Hamiltonian_error>1e-8:
        raise RuntimeError(
            "Authentic GetFEM oscillator violates its constitutive law "
            "or Hamiltonian: "+repr((coenergy_error,Hamiltonian_error))
        )

    def energy(position,momentum):
        return .5*stiffness*position*position+momentum*momentum/(2.*mass)

    # Discrete quadratic BDF2 chain-rule identity, not trapezoidal
    # integration of physical work or a claim about PETSc startup.
    a_q,a_p=q[2:],p[2:]
    b_q,b_p=q[1:-1],p[1:-1]
    c_q,c_p=q[:-2],p[:-2]
    bdf2_energy_rate=(
        energy(a_q,a_p)-energy(b_q,b_p)
        +energy(2*a_q-b_q,2*a_p-b_p)
        -energy(2*b_q-c_q,2*b_p-c_p)
        +energy(a_q-2*b_q+c_q,a_p-2*b_p+c_p)
    )/(2.*dt)
    balance_defect=bdf2_energy_rate+dissipation[2:]-input_power[2:]
    max_defect=float(np.max(np.abs(balance_defect)))
    if max_defect>1e-8:
        raise RuntimeError(
            "Original BDF2 oscillator step-power identity failed: "
            +str(max_defect)
        )

    # These scalar quantities exist on every MPI rank. Only the root
    # writes the shared figures; no need to render one copy per rank.
    if PETSc.COMM_WORLD.getRank()!=0:
        return None
    root=Path(folder)
    png=root/"png"
    svg=root/"svg"
    gif=root/"gif"
    data=root/"npz"
    metadata=root/"json"
    for directory in (png,svg,gif,data,metadata):
        directory.mkdir(parents=True,exist_ok=True)

    def save_both(fig,stem):
        fig.savefig(png/(stem+".png"),dpi=180)
        fig.savefig(svg/(stem+".svg"))
        plt.close(fig)

    fig,(ax1,ax2)=plt.subplots(

Verification

The expected energy variation satisfies

\[H(t)-H(0)=\int_0^t\bigl[f(s)e_p(s)-c\,e_p(s)^2\bigr],\mathrm ds.\]

The continuous work integral is useful for understanding the physics, but it should not be confused with the generic nodal-trapezoid plot, which is only an approximation for BDF2 (Energy, powers and time discretization (v1.3.0)). This specific example separately measures its own discrete quadratic identity, not an identity supplied by compute_powers(). This example uses the original quadratic Hamiltonian and fixed-step BDF2, so every step \(n\geq2\) also has the exact discrete quadratic identity

\[\frac{ H(z_n)-H(z_{n-1}) +H(2z_n-z_{n-1})-H(2z_{n-1}-z_{n-2}) +H(z_n-2z_{n-1}+z_{n-2}) }{2\Delta t} +c\left(\frac{p_n}{m}\right)^2 -f(t_n)\frac{p_n}{m}=0.\]

This identity is obtained by multiplying the original semi-discrete oscillator equation by its current co-energy, not by applying a trapezoidal rule to a saved power plot. It covers BDF2 steps \(n\geq2\), not the internal PETSc BDF2 startup stages, which require a separate analysis.

The native qualification checks the physical model, BDF2 time stepping and GetFEM weak forms, starting from exactly consistent algebraic co-energies with no artificial initial time step. It uses MUMPS in MPI 1 and 2 and measures the actual algebraic relations \(e_q=kq\), \(e_p=p/m\), both differentiated BDF2 equations, the exact step energy-power defect and the complete MPI state trajectory. The independent reference is the forced two-state ODE, integrated by a high-accuracy RK4 scheme, not a replacement SCRIMP model:
